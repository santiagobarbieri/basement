# ENDO audit

Date: 2026-10-12. Source: `cf7f971a3eabce9013fa1c1082df2c32d4111b89`.

## Result

The original editor runs in Chrome on this Mac. Painting, undo/redo, project
serialization/reopening, IndexedDB recovery, and PNG/JPEG encoding passed the
isolated smoke test. The project round trip produced exactly the same PNG bytes.
This is an engine audit, not the BASEMENT redesign or a complete regression suite.

Open with a double-click on `scripts/run-endo.command`. The original local server
serves `http://127.0.0.1:9340/index.html`; no JS dependency installation or build is
needed. Python and the installed browser are sufficient. The server is optional
for the editor's current browser-based save path.

## Inventory and structure

| Area | Observed state |
| --- | --- |
| Rendering | Canvas 2D; material volume and lighting are simulated in pixel calculations. No independent 3D scene/viewer or WebGPU engine found. |
| Brushes shown in the library | 16: Metal, Chrome, Neon, Ink, Spray, Calligraphy, Lightning, Pencil, Outline, LIME, Paint Brush, Crayon, Sand, Cement, Metal Relief, Metal Foam. |
| Additional brush behavior | Fusion combines materials. Nine legacy brush renderers remain loadable but are removed from the visible library: Halftone, Pixel, Fur, Aurora, Glitch, Ribbon, Dots, Stamps, Hatching. |
| Graphic effects | Warholian Velvet, Xerox Burn, Newsprint, Iconprint; shared with the bundled Atto code. Preserve them during integration. |
| Layers | Stroke/image/reference layers, transforms, visibility, locking, opacity, duplication, groups, five blend modes, erase/restore masks. |
| Creation | Mirror, mosaic, mandala, grid/snap, screens containing multiple frames, material backgrounds, imported images/tracing references, history, presets. |
| Project storage | JSON `.endo`, schema versions 2/3 accepted; data-URL images. IndexedDB `endo-local-workspaces`, key based on URL pathname. |
| Export | PNG/JPEG/WebP, transparent PNG, scopes for current frame/screen/project and ZIP output. Native-size export is capped at 24 megapixels. |
| Imports | Browser image decoding via file input, paste and drop; PNG/JPEG/WebP supported by the browser path. Each import was inspected in source, not individually tested. |
| Text/shapes/eyedropper | No corresponding implemented tool found in the current ENDO rail. Do not invent tools merely from the proposed AGENTS list. |

`index.html` contains the engine and most state/UI logic inline (995 lines, many
very long). `endo-hub.js` extends menus, effects, screens, adjustments and project
validation. `endo-layout.js` and `.css` move existing controls into the current
layout. `collection.js` uses File System Access save dialogs where available and
download fallback otherwise. `basement_server.py` also has a token-protected
native Save As endpoint, but the current `collection.js` does not call it.
`atto/effects.js` is loaded by ENDO; the separate Atto editor is outside this audit.
`assets/fonts/druk.otf` already exists upstream; confirm its exact identity and
licensing before reusing it as BASEMENT branding.

## Verified shortcuts and rail

Runtime tooltips/source confirm Select V, Brush B, Eraser E, Restore mask R,
Mirror M, Grid G, Fusion F. Mosaic, Mandala, move tracing reference and brush
picker are also present. Existing shortcuts include Cmd-Z / Cmd-Shift-Z,
Cmd-S, Cmd-D, Cmd-G / Cmd-Shift-G, Delete and Space pan. The upstream rail differs
from the inferred 13-tool list in AGENTS; use real behavior as the inventory.

## Integration work and risks

1. Separate state/rendering/persistence hooks from DOM layout before replacing chrome;
   multiple scripts currently wrap globals and move DOM controls.
2. Replace pathname-keyed single-workspace autosave with per-artboard identity and
   BASEMENT disk persistence. Current storage is not `~/Basement/*.artboard`.
3. Wrap project encode/decode and `renderBoardBlob` for real disk saves, thumbnails,
   PNG/JPEG exports, and recovery. Preserve effects and legacy decoding.
4. Apply the supplied visual reference while keeping real controls reachable;
   expose advanced brushes/settings in appropriate panels rather than removing them.

Canvas CPU pixel loops and large embedded images are performance/memory risks.
The export cap can silently downscale a large native-size board. Browser storage
alone is not a portable backup. No claim of a full 3D mode is justified.

## Proposed v1 checkpoint

Retain the current real painting functions, 16 visible brushes plus Fusion,
legacy-project support, effects, masks, symmetry modes, and multi-frame project
data; add BASEMENT chrome and `.artboard` disk storage in their scheduled phases.
Santi should open the original editor once and confirm this inventory before the
architecture phase. No engine source was modified during this audit.
